# Harness test migration

The retired `runAgentLegacy` implementation is no longer called. Its tests assumed prose-only completion, automatic task-specific toy/fixture orchestration, synthesized dossiers after empty output, repeated malformed-call downgrades, and approval for every effect. Those assumptions conflict with the current mission contract and would validate behavior the product must no longer perform.

The former `agent-approval.test.mjs` mixed those retired behaviors with durable review checks. The retained cases cover orphaned approval invalidation, incomplete-artifact review, evidence identifiers and claim labels, scientific versus software status, document validation limits, and failed Proto validation persistence. A regression now asserts that retired topic-specific fallback generators are absent from the production module. The canonical workspace-path mock supplies the actual path-normalization contract.

The unreachable legacy context loop, artifact recovery loop, offline scenario routing, and static dossier generators were removed after a TypeScript AST call-graph audit. They are not available as alternate production completion paths. Persisted manual approval lifecycle handling remains for compatibility with previously stored approval records. Generic Harness completion always requires the current mission contract and independent artifact/evidence checks.

`agent-harness-service.test.mjs` runs the public `AgentService` lifecycle with the real database, real workspace filesystem, actual Harness controller/store, and explicit model/MCP boundary fixtures. It verifies scoped automatic writes, independent finish acceptance, rejection of prose-only and empty completion, mission-bound network capabilities, denial outside scope, plan-mode tool visibility, required DNA material binding, terminal startup errors, and cancellation of an owned session. Every fixture has a bounded terminal wait; a missing event fails rather than hanging the whole suite.

The existing `harness-controller.test.mjs` and `harness-integration.test.mjs` independently cover durable result replay, uncertain effects, context and execution budgets, compaction, preserved mandatory reads/deliverables, exact artifact digests, result pagination, repeated tool discovery, existing-file read receipts, source changes, and current real Python MCP schemas. Tests do not translate a failed model turn into automatic fixture success. Native and real-model task outcomes remain separate evidence gates.

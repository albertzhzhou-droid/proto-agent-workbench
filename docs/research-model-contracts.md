# Research plan and evidence contracts

The logical Research Model boundary is in `apps/proto-workbench/src/shared/research-plan.ts` and `research-evidence-graph.ts`. These modules use JSON, Zod and types; they do not import Electron, React, SQLite or scientific workers. The host compiler and evidence adapter reside in `src/main/services`.

`compileResearchPlan(spec, catalog, hostFacts)` performs deterministic static validation and lowers a StudySpec into the existing WorkflowDraft. Rejection returns diagnostics without a plan or workflow. The application supplies checked source and runtime fingerprints; these fields are never execution grants. The method contract is a projection of `proto_compute_run` plus the current canonical Compute catalog, including input schema, file inputs, existing maturity and quantity profile. The contract digest is a content identity, not an invented scientific method version or signature.

The compiler requires explicit data version, source digest, entity identities, units, reference version, assumptions and step roles. Units are generated by `scripts/generate-scientific-units.py` from the existing Python `scientific_contracts.py` authority; `--check` detects drift. File input paths must match declared dataset versions. A required step cannot depend on optional or superseded work. Superseded steps remain in the frozen specification with a reason, but are absent from the executable DAG.

The existing WorkflowDraft does not forward the Compute request's optional `dataset_manifests` and `quantity_bindings`. This profile therefore rejects required `quantity-bound` obligations. It does not certify field-level protein/residue mappings, statistical estimands, missing-value semantics, or numeric output units. Per-method output schemas, expanded Quantity output coverage and general resource policies remain unsupported. The existing reviewed Python quantity adapters retain their original scope.

`collectManagedResearchEvidence` reopens existing run artifacts and checks Study/workflow/revision, step identity, retained run binding, the complete resolved request, runtime/implementation fingerprint and saved file-input digests. It performs no scientific computation. A changed or unavailable live source prevents current completion while intact historical results retain verified integrity. An optional immutable-snapshot verifier can establish retained dataset integrity independently of current source freshness.

Evidence edges point from an input or supporting object to the dependent object. This direction also applies to `derived_from`. Only `consumes`, `produces` and `derived_from` must be acyclic; argument/support relationships may contain cycles. Invalidation changes a new freshness projection and never rewrites original graph versions or changes retained hashes or integrity. Direct dataset-to-attempt dependencies preserve independent branches. Scientific Diff separates source/version, sample inclusion, units, parameters, references, methods, runtime, seed and claims; it makes no causal attribution.

Completion requires all required steps and deterministic obligations to have checked evidence bound to this plan and step. Known optional failures remain visible without independently blocking completion. Every unknown effect and every active owned attempt blocks completion, including optional and earlier attempts. Historical attempts supplied to the adapter remain in the completion facts; a later success cannot erase their unknown effects. Human review is never manufactured from successful execution, and accepted-in-scope review must bind to the exact plan and step. Completion means these evidence obligations are met; scientific acceptance remains separate.

Focused verification:

```text
node --experimental-strip-types --test tests/research-plan.test.mjs tests/managed-research-evidence.test.mjs
python scripts/generate-scientific-units.py --check
```

The tests cover deterministic lowering, real catalog projection, bad units and identities, source/runtime drift, graph cycles and independent invalidation, optional/unknown-effect semantics, review binding, cross-Study rejection, retained result tampering and downstream argument substitution. Fixtures testing host checks do not establish scientific or runtime-distribution acceptance.

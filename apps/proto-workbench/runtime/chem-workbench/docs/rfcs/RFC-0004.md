# RFC-0004: Ownership of Explicit, Average, and Ensemble Structures

**Status:** Draft for alpha implementation  
**Target:** Periodic structure ownership model `v1alpha1`  
**Last updated:** 2026-09-02  
**Decision owners:** Core schema, periodic-structure, interoperability, and compute maintainers

## Summary

ChemIR distinguishes an explicit atomic configuration, an average crystal, and
a material ensemble. `PeriodicStructure.semantics` is the required discriminator
between `explicit_configuration` and `average_crystal`. An explicit site is a
real atom with occupancy one. An average site owns a probability distribution
over species and may include probabilistic vacancy. A `MaterialEnsemble` owns
correlations, sampling semantics, members, and member probabilities; it does
not copy the base average structure's occupancy table.

Only explicit three-dimensional periodic structures are accepted by the core
`chemir/v1alpha1` schema and are in the intended software-only core-v1
conformance profile. `average_crystal` is a reserved discriminator for the
post-v1 disorder profile; average structures, defects, and ensembles remain
post-v1 experimental work.

## Motivation

Partial occupancy is not a slightly incomplete atom list. An average CIF model,
a concrete supercell realization, a vacancy defect, and a statistical ensemble
make different scientific claims. Collapsing them into one site table can create
fractional atoms in atomistic calculations, duplicate disorder ownership, lose
correlations, or imply equivalence between unrelated supercells.

This RFC establishes one owner for each fact and requires explicit conversion
evidence between models.

## Scope

This RFC defines:

- common periodic structure fields;
- `explicit_configuration` and `average_crystal` site semantics;
- `MaterialEnsemble` ownership;
- defect and parent/child mapping rules;
- conversion and compute-readiness gates; and
- validation, diagnostics, and alpha decision points.

It does not define a complete crystallographic ontology, magnetic CIF,
modulated or incommensurate structures, quasicrystals, amorphous bulk models,
phonon ensembles, molecular dynamics trajectories, or thermodynamic phase
mixtures.

## Common `PeriodicStructure` contract

`PeriodicStructure` is a top-level RFC-0001 envelope. Its payload contains at
minimum:

```json
{
  "semantics": "explicit_configuration",
  "lattice": {
    "vectors": [[3.57, 0, 0], [0, 3.57, 0], [0, 0, 3.57]],
    "unit": "angstrom",
    "periodic_boundary_conditions": [true, true, true]
  },
  "coordinate_system": "fractional",
  "sites": [
    {"id": "site:C-1", "element": "C", "coordinates": [0, 0, 0], "occupancy": 1}
  ]
}
```

The alpha core schema requires `semantics` and then either a structured body
(`lattice`, `coordinate_system`, and `sites`) or at least one source-backed
`representation`. A representation-only object is preserved for later parsing;
it is not structure-consistent or compute-ready. Structured fields own:

- three non-coplanar lattice vectors and their unit;
- per-axis periodic boundary flags;
- coordinate-system declaration;
- stable site identifiers and coordinates;
- an asserted or derived symmetry record with evidence, tool version, and
  tolerance when present;
- basis role as primitive, conventional, or supercell when asserted; and
- an integer parent transformation and origin shift when a parent basis is
  declared.

The first release profile accepts only three-dimensional periodic structures
with all periodic flags true. Other dimensionality may be preserved by an
adapter under a non-normative profile, but it cannot be approximated silently
as a three-dimensional crystal.

The lattice must be finite, non-singular, and have positive oriented volume
under the documented vector convention. Site identifiers are unique within one
structure. Coordinates must be finite. Fractional coordinates outside the
conventional unit interval are not automatically wrapped by canonicalization;
a normalization operation may create a new structure and provenance record.

## Ownership matrix

| Information | Explicit `PeriodicStructure` | Average `PeriodicStructure` | `MaterialEnsemble` |
|---|---|---|---|
| Lattice, PBC, coordinate system | Owns | Owns | References base; does not copy |
| Concrete atom at each child site | Owns | Forbidden | Present only through referenced members |
| Site marginal species/occupancy distribution | Forbidden except occupancy one | Owns | Must not copy |
| Vacancy as a probabilistic site component | Forbidden | Owns | Must not copy |
| Missing parent atom in a concrete defect | Owns through defect event and mapping | Forbidden as concrete absence | References explicit member evidence |
| Correlation groups and correlation scope | Does not own general disorder correlations | Does not own | Owns |
| Sampling algorithm and seed policy | Provenance for one generated object | Does not own | Owns |
| Member list and probabilities/weights | Does not own | Does not own | Owns |
| Symmetry assertion for represented structure | Owns | Owns | May summarize only as derived evidence |
| Parent/child site mapping | Owns when a concrete child is derived | May identify parent basis only | Requires mapping for each explicit member |

If the same scientific fact appears in two owner locations, validation fails
with `STRUCTURE_OWNERSHIP_DUPLICATE`; the compiler must not choose one silently.

## Explicit configuration

An explicit site has the conceptual alpha shape:

```json
{
  "id": "site:Si-1",
  "element": "Si",
  "coordinates": [0, 0, 0],
  "occupancy": 1
}
```

Rules are:

- `semantics` is exactly `explicit_configuration`.
- each site contains exactly one real element and an optional isotope mass
  number supported by the core schema.
- occupancy is required and is the exact JSON number `1`.
- a vacancy pseudo-element or a species distribution is forbidden.
- site identity and coordinates are explicit even if symmetry could generate
  equivalent sites.
- composition is calculated from the concrete site list and has integral atom
  counts for the represented cell.
- a declared symmetry assertion is checked against all sites using its recorded
  tolerance. Toolkit-derived symmetry never silently replaces the assertion.

The core atomistic compute path accepts only an explicit configuration that
passes these invariants and the selected backend capability profile.

## Average crystal

An average site has the conceptual alpha shape:

```json
{
  "id": "site:mixed-1",
  "coordinates": [0, 0, 0],
  "species_distribution": [
    {"species": {"element": "Si"}, "occupancy": 0.70},
    {"species": {"element": "Ge"}, "occupancy": 0.25},
    {"species": {"kind": "vacancy"}, "occupancy": 0.05}
  ]
}
```

Rules are:

- `semantics` is exactly `average_crystal`.
- every component occupancy is a finite decimal in `[0, 1]`.
- species components are unique after canonical species identity comparison.
- the site occupancy sum is one within the active profile tolerance. The alpha
  authored-data tolerance is `1e-8`; an importer may preserve a looser source
  tolerance but must issue a diagnostic and cannot claim core consistency until
  a named normalization/review step resolves it.
- probabilistic vacancy is permitted only as a distribution component; it is
  not an atom and has no atomic number, mass, or electronic state.
- the average structure owns only site marginals. It does not claim that sites
  are independent and does not own cross-site correlations.
- average composition is derived from occupancy-weighted species counts and
  may be fractional.

An average crystal is not in the core-v1 normative profile. Importing partial
occupancy from CIF creates an experimental average object and a capability/loss
report. It must never be relabeled as an explicit configuration merely because
a backend accepts an atom list.

## `MaterialEnsemble`

A `MaterialEnsemble` references exactly one base average structure and selects
one representation mode:

```json
{
  "base_structure": "crystal:si-ge-average",
  "representation": "explicit_members",
  "members": [
    {"structure": "crystal:member-1", "probability": 0.5},
    {"structure": "crystal:member-2", "probability": 0.5}
  ],
  "correlation_scope": {},
  "sampling_strategy": {}
}
```

The other allowed alpha representation is `sampling_model`, which contains a
bounded versioned sampling specification instead of a materialized member list.
`explicit_members` and `sampling_model` are mutually exclusive in alpha.

Rules are:

- the base reference resolves to `PeriodicStructure` with
  `semantics: average_crystal`.
- every materialized member resolves to `PeriodicStructure` with
  `semantics: explicit_configuration`.
- each member provides a complete base-to-member site mapping and cell
  transformation or explicitly reports why a mapping is unresolved.
- probabilities, when declared, are finite and non-negative and sum to one
  within `1e-8`. Unnormalized statistical weights use a distinct field and
  cannot be called probabilities.
- correlation scope, allowed configurations, constraints, sampling algorithm,
  deterministic seed or seed policy, and tool identity are ensemble-owned.
- the ensemble does not repeat the base lattice or species-distribution table.
- a member does not own its ensemble probability; the ensemble does.

An ensemble semantic hash binds the base, correlations, strategy, members, and
probabilities. It does not imply that the members are exhaustive, converged, or
thermodynamically representative unless a separate evidence claim establishes
that under a named protocol.

## Defect events and parent/child mapping

A concrete defective structure remains an explicit configuration. It may
contain defect events whose alpha kinds are `vacancy`, `substitution`,
`interstitial`, `antisite`, and `complex`.

Each event records:

- an immutable parent-structure reference;
- the child explicit-structure reference or owning child ID;
- event kind;
- parent-to-child site mapping for all unaffected and affected sites;
- created, removed, or substituted site/species references;
- integer cell transformation and origin shift when the cell changes;
- composition delta under a declared counting basis;
- charge-state assertion when applicable, with evidence; and
- producer, method, version, parameters, and source/provenance references.

For a vacancy, the child site list simply omits the real atom. The defect event
references the missing parent site. The child must not add a fake vacancy atom
or an occupancy-zero site.

For an interstitial, the new child site has no parent site and is identified in
the event. For substitution and antisite events, the mapping preserves the site
relationship while the event records the species change. A `complex` event
contains typed constituent events and must not hide an untyped net composition
change.

Charge state is an assertion about the defect model, not an instruction to put
finite `charge` or `multiplicity` on a periodic `ElectronicState`. Periodic
charge semantics remain an open item in RFC-0003.

## Model conversion

### Average to explicit

Average-to-explicit conversion is a materialization operation, not
canonicalization. It requires:

- source average semantic hash;
- integer supercell transformation;
- named disorder strategy and version;
- correlation model or an explicit declaration of independent-site sampling;
- deterministic seed and random-number algorithm when sampling is used;
- selected occupancies/species for every explicit site;
- complete base-to-child mapping;
- producer/tool/package identity; and
- a machine-readable loss and assumption report.

The operation creates a new explicit structure. It never mutates the average
object. The output cannot claim automatic semantic equivalence to the average
or to another realization.

### Explicit to average

Explicit-to-average aggregation requires an explicit member set, base mapping,
weighting policy, cell/basis alignment, and symmetry/coordinate tolerances. It
creates a new average structure plus ensemble/provenance evidence. The compiler
must not infer this aggregation from one configuration or from structural
similarity alone.

### Basis and supercell changes

Primitive, conventional, and supercell conversions record the integer
transformation, origin shift, site mapping, tool/version, tolerance, and loss
report. Different cells do not receive automatic equal semantic hashes. A named
comparator may establish equivalence only under an explicit profile.

## Compute-readiness policy

For `v1-core-structure-compute`:

- the target is an explicit three-dimensional periodic structure;
- every site is a real atom with occupancy one;
- lattice, PBC, coordinates, required species identity, and backend-specific
  requirements are complete;
- no unresolved disorder or unmapped defect semantics affect the task; and
- the capability manifest supports the exact entity, task, calculator, and
  electronic-state treatment.

An average crystal is blocked from an atomistic plan unless a later, named
backend profile explicitly supports average occupancy. A disorder strategy may
produce a new explicit target, but the planner must show that target and its
materialization evidence rather than treating the average as ready.

An ensemble is not silently reduced to its first member. The calculation must
target a named explicit member or a separately specified ensemble computation
profile. Results from one member cannot be written back as a result for the
whole ensemble.

## Diagnostics

| Code | Default severity | Condition |
|---|---|---|
| `PERIODIC_SEMANTICS_UNKNOWN` | error | Missing or unsupported discriminator |
| `LATTICE_SINGULAR` | error | Lattice is non-finite, singular, or non-positive under vector convention |
| `PERIODIC_FLAGS_UNSUPPORTED` | error at core readiness | PBC is outside supported dimensionality |
| `SITE_ID_DUPLICATE` | error | Site identifier occurs more than once |
| `EXPLICIT_SITE_NOT_CONCRETE` | error | Distribution, vacancy, or non-unit occupancy occurs in explicit structure |
| `AVERAGE_OCCUPANCY_RANGE` | error | Occupancy is outside `[0, 1]` |
| `AVERAGE_OCCUPANCY_SUM` | error/review_required by import profile | Site sum exceeds the active tolerance |
| `STRUCTURE_OWNERSHIP_DUPLICATE` | error | Marginals, correlations, or probabilities are stored by multiple owners |
| `ENSEMBLE_PROBABILITY_INVALID` | error | Probabilities are invalid or do not sum to one |
| `ENSEMBLE_MEMBER_TYPE` | error | Member is not an explicit configuration |
| `DEFECT_MAPPING_INCOMPLETE` | error at readiness | Parent/child relation cannot be resolved |
| `DEFECT_COMPOSITION_MISMATCH` | error | Recorded and derived composition deltas disagree |
| `AVERAGE_STRUCTURE_COMPUTE_BLOCKED` | error | Unsupported average object was sent to atomistic planning |
| `STRUCTURE_EQUIVALENCE_UNPROVEN` | review_required | Conversion would assert undeclared equivalence |

## Canonicalization

Lattice, PBC, coordinate system, site IDs, site content, coordinates, symmetry
assertions, basis relations, and defect relations participate in semantic
hashing. Decimal and unit rules come from RFC-0001.

Site arrays preserve authored order in artifact serialization. The semantic
projection treats sites as a schema-declared set sorted by stable site ID;
duplicate IDs are errors. Species distributions are sets sorted by canonical
species identity. Coordinate rounding, symmetry expansion, wrapping, and cell
reduction are never implicit canonicalization steps.

Changing an occupancy, site mapping, correlation, member probability, strategy,
or tolerance changes semantics and invalidates dependent plans and approvals.

## Conformance tests

### Core explicit fixtures

1. Silicon diamond with positive lattice volume, full PBC, fractional
   coordinates, unit occupancy, and a checked symmetry assertion.
2. FCC copper with an explicit calculator-ready cell.
3. Singular lattice, invalid PBC, duplicate sites, vacancy pseudo-atom, species
   distribution, and non-unit occupancy as negative fixtures.
4. Primitive-to-supercell transformation with complete deterministic mapping.

### Experimental average and ensemble fixtures

1. Si/Ge/vacancy average site with valid probabilities.
2. Occupancy below zero, above one, duplicated species, and sums outside
   tolerance.
3. Two explicit member configurations with a valid base mapping and
   probabilities.
4. Duplicated occupancy tables in the ensemble as an ownership error.
5. Correlated sampling versus explicitly declared independent sampling.
6. Reproducible materialization with fixed seed and algorithm, and changed
   output after a bound strategy input changes.

### Defect fixtures

1. Explicit silicon vacancy supercell with omitted child atom and mapped parent
   vacancy event.
2. Substitution and interstitial with correct composition deltas.
3. Fake vacancy species, incomplete site mapping, non-integer cell
   transformation, and inconsistent composition delta as negative fixtures.

These experimental fixtures do not establish normative core-v1 conformance.

## Alpha decision register

Fixed by the alpha ownership model: `PeriodicStructure.semantics` distinguishes
`explicit_configuration` from the reserved `average_crystal` model; explicit
sites are real atoms of occupancy one; average sites own marginal distributions;
vacancy is probabilistic only in average sites and an event/missing parent site
in explicit defects; ensemble members are explicit; and `MaterialEnsemble`
exclusively owns correlations and probabilities. The core `chemir/v1alpha1`
schema accepts only `explicit_configuration`; it must reject
`average_crystal` rather than hiding average semantics in extensions.

Open items:

| Open item | Required resolution |
|---|---|
| Site identity | Freeze identifiers across symmetry expansion, cell changes, imports, and round trips |
| Occupancy tolerance | Review `1e-8`, define source versus normalized tolerance, and freeze per-profile behavior |
| Species identity | Define isotope, oxidation, pseudo-species, and vacancy component vocabulary |
| Symmetry subset | Freeze supported groups/settings, operation representation, tolerance, and assertion/derivation policy |
| Correlation schema | Define bounded groups, constraints, range, and composition-condition semantics |
| Sampling protocol | Freeze random algorithm, seed encoding, deterministic ordering, and provenance record |
| Defect schema | Freeze event nesting, charge-state convention, parent basis, and complex-event validation |
| Ensemble statistics | Distinguish probabilities, degeneracies, unnormalized weights, and thermodynamic weights |
| Comparator profiles | Define translation, permutation, symmetry, cell, and tolerance equivalence without changing hash rules |
| Backend support | Decide whether any reviewed average-occupancy backend profile is in scope after core v1 |

## Acceptance criteria

RFC-0004 is implemented for the core alpha scope when:

- the core schema accepts only explicit sites with required occupancy one and
  rejects average, vacancy, and ensemble semantics;
- validators enforce the applicable explicit ownership rules and emit stable
  diagnostics;
- core compute planning accepts the silicon and copper explicit fixtures and
  blocks the average fixture;
- a vacancy configuration contains no fake vacancy atom; and
- no comparator or hash path automatically equates different supercells,
  disorder models, average structures, or ensemble members.

The later `disorder-defect-ensemble` alpha profile is implemented only when its
separate schemas enforce mutually exclusive explicit and average shapes and its
materializer creates a new explicit object with deterministic strategy, seed,
mapping, provenance, and loss evidence.
